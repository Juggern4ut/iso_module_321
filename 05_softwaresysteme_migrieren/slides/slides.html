Modul 321

Lektion 05: Softwaresysteme migrieren

Bestehende Systeme schrittweise oder in einem grossen Wechsel modernisieren

Lernziele

  • Ich kann erklären, was eine Migration von Softwaresystemen bedeutet.
  • Ich kann Big Bang und Strangler Pattern unterscheiden.
  • Ich kann typische Risiken von Migrationen benennen.
  • Ich kann begründen, wann eine schrittweise Migration sinnvoll ist.
  • Ich kann für einfache Szenarien eine passende Migrationsstrategie auswählen.

Was bedeutet Migration?

Eine Migration verändert ein bestehendes System gezielt, zum Beispiel Architektur, Technologie, Datenhaltung oder Betriebsmodell.

Typische Auslöser

  • Veraltete Technologie
  • Zu langsame Änderungen
  • Skalierungsprobleme
  • Hohe Betriebs- oder Wartungskosten

Wichtig dabei

  • Daten dürfen nicht verloren gehen.
  • Nutzer möglichst wenig stören.
  • Risiko und Aufwand müssen steuerbar bleiben.

Zwei Grundstrategien

Big Bang
Altes System wird in einem grossen Schritt ersetzt.
vs.
Strangler Pattern
Neue Teile übernehmen das System schrittweise.
Beide Strategien können sinnvoll sein. Die bessere Wahl hängt von Risiko, Systemgrösse, Zeitdruck und Testbarkeit ab.

Big Bang

Grundidee

  • Das neue System wird fertig gebaut.
  • Zu einem definierten Zeitpunkt wird umgeschaltet.
  • Danach läuft möglichst nur noch das neue System.

Vorteile

  • Klare Trennung alt gegen neu
  • Keine lange Parallelwelt
  • Weniger Übergangslogik

Risiken

  • Hoher Druck am Umschalttag
  • Fehler wirken sofort grossflächig
  • Rollback kann schwierig sein

Wann Big Bang passen kann

  • Das System ist klein und fachlich überschaubar.
  • Es gibt klare Testfälle und gute Datenkontrolle.
  • Ein kurzes Wartungsfenster ist akzeptabel.
  • Die alte Lösung ist technisch schwer parallel betreibbar.

Je kritischer das System, desto riskanter wird ein grosser Einmalwechsel.

Strangler Pattern

Neue Funktionen oder Teilbereiche werden schrittweise vor das alte System gesetzt und übernehmen nach und nach mehr Verantwortung.

Alt-System
liefert bestehende Funktionen
umleiten
Neue Services / Module
ersetzen Teil für Teil

Typischer Ablauf beim Strangler

1. Begrenzen

  • Teilbereich auswählen
  • Schnittstelle definieren

2. Ablösen

  • Neue Funktion entwickeln
  • Traffic gezielt umleiten

3. Entfernen

  • Altcode stilllegen
  • Alte Abhängigkeiten abbauen

Vorteile und Nachteile des Strangler Pattern

Aspekt Vorteil Nachteil
Risiko Kleinere Schritte sind leichter kontrollierbar. Die Migration dauert oft länger.
Betrieb Altes System bleibt zunächst nutzbar. Paralleler Betrieb erzeugt Zusatzaufwand.
Qualität Feedback kommt früher aus echten Teilumstellungen. Übergangsschnittstellen können komplex werden.

Entscheidungskriterien

Fragen zum System

  • Wie kritisch ist ein Ausfall?
  • Wie gross und unübersichtlich ist der Altbestand?
  • Wie gut sind Tests, Monitoring und Datenqualität?
  • Kann ein Teilbereich sauber isoliert werden?

Fragen zum Umfeld

  • Wie viel Zeit und Budget steht zur Verfügung?
  • Wie oft darf produktiv umgestellt werden?
  • Kann das Team zwei Welten gleichzeitig betreiben?
  • Wie teuer wäre ein Fehler beim Wechsel?

Praxisbeispiel: Online-Shop

Big Bang

  • Kompletter Shop wird neu gebaut.
  • Am Stichtag wird DNS oder Routing umgestellt.
  • Geeignet nur bei hoher Sicherheit und guter Testabdeckung.

Strangler

  • Zuerst Produktkatalog auslagern.
  • Danach Warenkorb oder Suche ersetzen.
  • Checkout erst spät migrieren, weil er fachlich kritisch ist.

Wichtiger Grundsatz: mit wenig kritischen Bereichen beginnen, Erfahrung sammeln, dann Kernprozesse angehen.

Merksätze

  • Migration ist kein reines Technikprojekt, sondern immer auch Betriebs- und Risikoarbeit.
  • Big Bang ist einfach im Konzept, aber riskant im Moment der Umschaltung.
  • Strangler Pattern reduziert Risiko, erhöht aber die Dauer und Übergangskomplexität.
  • Die passende Strategie ergibt sich aus Kontext, nicht aus Mode.
Gute Migrationen zerlegen grosse Unsicherheit in kleine, überprüfbare Schritte.
